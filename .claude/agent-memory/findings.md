- 2026-05-30 — build/browserslist — `.browserslistrc` had `iOS >=14` / `Safari >=14` which causes esbuild destructuring errors with Angular 19.2; raising to `>=16` fixes it (FRED targets iOS 16+)
- 2026-05-30 — npm/esbuild — `npm audit fix` can downgrade esbuild (0.28→0.25) which breaks the build; pin esbuild at 0.28.x with explicit `npm install esbuild@0.28.0 --save-dev` after any audit fix run
- 2026-05-30 — mfu — `MonthlyFreedomUpdateData.equityLevel` (1-6) is already computed server-side and available via `checkShouldShow()` — use it for pig avatar level without an extra API call
- 2026-05-30 — angular — after B6 overhaul, ~50 standalone component imports across 20+ files were stale; angular-compiler TS-998113 warnings are the canonical signal to clean them
- 2026-05-30 — typescript — dynamic `import('module-name')` even cast `as any` still triggers TS 2307 if the module has no resolvable types; `// @ts-ignore` on the import line is the minimal fix
- 2026-05-30 — User.java — Lombok @Getter/@Setter on class auto-generates getters for all private fields; only manually-added inline getters (e.g., from Bucket C merge) duplicate what Lombok already provides — watch for duplicates
- 2026-05-30 — ITPM/today.html — dollar sign in date-derived password must use String.fromCharCode(36) not a template literal to avoid any shell/interpolation stripping when the ITPM skill writes the file via heredoc or script
- 2026-05-30 — sse-streaming — Spring SseEmitter emits `data:<json>\n\n` WITHOUT a space after the colon; frontend parsers that gate on `line.startsWith('data: ')` (with a space) will silently drop every event (chat.service.ts:83)
- 2026-05-30 — chat/stream — `GET /api/chat/stream` returns HTTP 500 when `userId` is null because `userRepository.findById(null)` throws; frontend must always supply userId (validated via fetch test against running backend)
- 2026-05-30 — ionic/nav — `NavController` is a service from `@ionic/angular` (not standalone), injected via constructor only — never add it to `imports: []` in a standalone component; use `navigateBack(route)` for back animations
- 2026-05-30 — ionic/nav — `.section-card { padding: 16px }` is a global rule; cards that need edge-bleeding content (e.g. absolutely-positioned images) must explicitly override `padding: 0` and give their inner content wrapper its own `padding: 16px`
- 2026-05-30 — sass/deprecation — `darken()`/`lighten()` in component SCSS must be replaced with `color.adjust($c, $lightness: ±N%)` after adding `@use 'sass:color'` as the first line (before any `@import url(...)`);
- 2026-06-06 — plaid/change-bank — Backend GET /plaid/primary-bank-account returns field `accountSubtype` (lowercase t); frontend reads `accountSubType` (capital T). Pre-existing case mismatch (also in unchanged TS formatAccountDisplay); subtype always falls back to 'Checking'. Not introduced by FRED-124 but worth fixing.
- 2026-06-06 — verify/env — Angular CLI + @angular/compiler-cli are NOT installed in the verifier sandbox, so `ng build`/template type-checking can't run; only raw `tsc --noEmit` is available (emits 2 pre-existing tsconfig deprecation warnings, no module-resolution errors). Backend on :8080 and local.fredvested.com are unreachable (host-allowlist block), so Phases 2 & 3 cannot execute here.
- 2026-06-06 — frontend/test-runner — security `overrides` in package.json (`glob: ">=11.1.0"`, `minimatch: ">=10.2.5"`) force karma@6.4.4 onto incompatible majors → `ng test` crashes at karma `file-list.js:74` (glob v13 dropped sync `.found`; minimatch v10 default export is an object, not callable). Fix: nested override `"karma": {"glob":"^7.1.7","minimatch":"^3.0.4"}` then `npm install --legacy-peer-deps`. karma is a devDependency only, so glob7.2.3/minimatch3.1.5 (both patched) carry no production risk.
- 2026-06-06 — npm/install — repo has a pre-existing peer conflict: `@capacitor/push-notifications@8.1.1` needs `@capacitor/core@>=8`, but the repo pins `@capacitor/core@7.2.0`. `npm install` ERESOLVE-fails without `--legacy-peer-deps`. Always install this frontend with `--legacy-peer-deps`.
- 2026-06-06 — frontend/test-runner — verifier/CI must run a single spec headless: `ng test --include='**/<name>.spec.ts' --watch=false --browsers=ChromeHeadless`. Whole-suite `ng test` may surface legacy CLI-generated specs that are red; target the spec under test.
- 2026-06-06 — backend/tests — `./gradlew compileTestJava` works; `./gradlew test` runs JUnit 5 (useJUnitPlatform). The only existing test, `BackendApplicationTests`, is `@SpringBootTest` and FAILS without MySQL (DataSourceBeanCreationException). Builder-written `backend-unit` tests MUST be plain JUnit (no `@SpringBootTest`) so they need no DB; verifier runs them targeted via `./gradlew test --tests <FullyQualifiedClass>`.
- 2026-06-13 — tab3/scss — `npx tsc --noEmit` in frontend/ always emits TS5101/TS5107 (baseUrl and moduleResolution=node10 deprecated in TS7) regardless of HTML/SCSS changes — these are pre-existing tsconfig.json deprecation warnings, not compilation failures introduced by page-level work.
- 2026-06-07 — ionic/safe-area — custom `div` headers inside `ion-header` (no `ion-toolbar`) do NOT automatically receive Ionic's safe-area padding. Must add `padding-top: calc(env(safe-area-inset-top, 0px) + Npx)` explicitly (or the global `safe-area-top` class, which uses `!important` and loses any breathing gap).
- 2026-06-06 — verifier — `/code-review` invoked from inside the verifier SUBAGENT is UNVERIFIED (may hit nested-agent limits). The verifier prompt is defensive: the INLINE code-review is the reliable path the gate depends on; the `/code-review` skill call is best-effort ("IF you can invoke"). Subagents can invoke skills generally (builder-agent already invokes brainstorming/writing-plans), so the open question is specifically whether nested `/code-review` spawns. Confirm on the first real verifier run; if it errors noisily, soften the verifier prompt to inline-only.
- 2026-06-07 — verifier/safe-area-lint — `node test/ui/safe-area-lint.mjs --files=<scss>` is the runnable static floor for the FRED-124 notch class; it passed on the change-bank-account fix (`.blue-hero-header` inside `ion-header` now uses `calc(env(safe-area-inset-top,0px)+10px)`), matching the documented 2026-06-07 ionic/safe-area convention for custom div headers.
- 2026-06-13 — verifier/safe-area-lint — safe-area-lint.mjs flags `.custom-profile-header` (tab3 Option B) as an offender, but this is a FALSE POSITIVE: the div carries the global `.safe-area-top` class (global.scss:535 `padding-top: env(safe-area-inset-top,0px) !important`) which the linter cannot see — it only parses the component SCSS. When a header's safe-area comes from a global utility class, cross-check global.scss before treating the lint exit-1 as an in-scope fail.
- 2026-06-13 — verifier/env — Phase 3 UI (live render/screenshots/network) is NOT executable in this verifier sandbox: no built `frontend/www` and no `serve` bin (so `npm run start` fails), and no Chrome/computer-use MCP tools are present. ui-acceptance ACs can only be verified at the static floor (SCSS/HTML/global.scss + safe-area-lint) here; device-size screenshots and click-through must be deferred to an environment with the browser tools.
