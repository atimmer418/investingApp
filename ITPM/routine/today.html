Implementation Options
Option A Recommended
New shared theme/_form-fields.scss partial, applied scoped, with <ion-input> converted to native <input class="field-input">
Create a single theme/_form-fields.scss that mirrors the canonical onboarding .field-label / .field-input values using FRED palette literals (#2563EB, #0f172a, #6b7280, red error) — not the kyc-scoped --kyc-* vars. On each of the 7 target pages, convert the inputs to native <label class="field-label"> + <input class="field-input"> for a true pixel match, and @use the partial scoped under each page's root selector (not a blanket global rule) so My Profile's .field-label div and the onboarding components are provably untouched. Carry over focus + error/validation treatment to match onboarding.
Pros: true pixel match to onboarding; single shared source (AC-1); scoped application provably can't bleed into My Profile/onboarding (AC-4/AC-5); native inputs make label/placeholder/error states match exactly (AC-3). Cons: most markup churn — 25 fields converted from Ionic to native, so each page's form bindings (ngModel/validation/value events) must be re-verified. Risk: Medium — wide surface (25 fields), but frontend-only and tsc/ng build-verifiable; live render confirmed by you. Estimate: ~3–4 hr
Option B
Same shared partial, but keep <ion-input> and approximate via Ionic CSS variables
Author the shared partial against Ionic's form primitives — set --background, --border-width/--border-color, padding and the label slot via Ionic CSS custom properties — so the existing <ion-input>/<ion-item> markup stays and only styling changes.
Pros: far less markup churn; preserves Ionic's built-in form behavior (validation, value events) so lower behavioral-regression risk. Cons: won't truly pixel-match — Ionic's internal padding, label float, and the underline rendering differ from the native onboarding fields, and matching the red error state through Ionic vars is fiddly; risks AC-3 (focus/error parity) and AC-5 (looks "close but off"). Risk: Medium — visual fidelity gap vs the onboarding reference; may bounce on AC-3. Estimate: ~2–3 hr
Option C
Blanket-global the partial via global.scss (one import, no per-page wiring)
Define .field-input / .field-label once and import globally in global.scss so every page picks it up automatically, with no per-page @use.
Pros: least wiring — one import, fields styled everywhere by class. Cons: rejected — breaks AC-4/AC-5. Ground-truthed this morning: My Profile uses <div class="field-label"> (+ its own .field-label SCSS at L292) and the onboarding components define .field-input/.field-label — a global rule would bleed into both, restyling explicitly out-of-scope surfaces. Risk: High — silent regressions on My Profile / onboarding. Estimate: ~2 hr (but non-compliant)
