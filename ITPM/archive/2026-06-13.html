FRED-192 — Redesign Tab 3 (Settings) Page UI
The natural next step after the bank-account page shipped: give the Tab 3 settings hub a cleaner design while keeping the signature blue header (avatar + "My Account" welcome + "FRED" wordmark). All content and actions stay — Investment Management, Account & Security, Support & Legal — this is a pure visual lift. Today's job is to pick a direction: three real design mockups are below, each grounded in the FRED UI Style Guide. The winner becomes a separate build story. Tier 1 — acceptance criteria already in the backlog.
Medium
Why I Picked These
This is the cleanest momentum pick on the board. FRED-124 (Change Bank Account) just shipped, which migrated the last standalone settings page — but Tab 3 itself, the settings hub every one of those pages hangs off of, is still on the old look. FRED-192 finishes that thought: redesign the hub so the whole settings surface feels like one polished system before private beta. It's Tier 1 — the story already carries a Summary and Acceptance Criteria in the backlog, so it's build-ready with no triage gap. It's a pure visual lift (no backend, auth, or schema), which keeps it Medium-difficulty and a guaranteed completion. Because it's a UI overhaul, the deliverable today is a direction, not code: three real mockups below, all keeping the blue-header concept you already like. The chosen one becomes its own implementation story.
Strategic Alignment
FRED-192 sits squarely on the current mission: complete the UI overhaul on every remaining page. Tab 3 is the front door to settings — it's the screen users return to whenever they manage money, security, or support, so its polish sets the tone for the entire account experience. Redesigning it consolidates the settings surface onto one consistent design system (the same white-section-card pattern the just-shipped bank-account and security pages now use), eliminating the last visible seam between "new FRED" and "old FRED" before private beta.
Production Readiness Impact
Tab 3 is a high-traffic surface, so migrating it moves the needle on UI coverage — the production-readiness component weighted at 40 points. Shipping the redesign is expected to take Pages Migrated from 73% to ~76% and nudge the readiness score from 72 toward the mid-70s, the threshold where the difficulty bias starts allowing Hard work. Just as important, it closes the "no half-finished screens" gate on the most-visited settings page: once the hub matches the pages it links to, the entire account experience reads as one finished product at launch.

Potentially Out of Scope
  • Implementation of the chosen design — that's the follow-on build story, not today. Today is direction-only.
  • Any navigation or behavior change — this is visual-only; the settings rows route exactly where they do now.
  • Restyling the downstream settings pages themselves (security-settings, change-bank-account, etc.) — they're already migrated; only the hub changes.
  • Replacing the placeholder avatar image (tracked under FRED-122's pig-art work) — keep whatever the avatar shows today.
UX Considerations
  • Loading / empty: Tab 3 is static content (the section list is hard-coded), so there's no data-fetch state to design — but the avatar image and the profile action badge should not cause layout shift while they resolve.
  • Safe area: carry the safe-area-top handling on the blue header (the lesson from FRED-124 — a raw header div must honor env(safe-area-inset-top) or it sits under the notch).
  • Mobile-first at 390×844, verified at 430×932 (your daily driver); generous spacing, one job per screen; the full list fits without feeling cramped.
  • FRED palette + Manrope + Material Symbols only; light mode forced; no competing patterns.
  • Design consistency: the white-section-card pattern now used by security-settings, my-profile, and the just-shipped change-bank-account is the safest baseline — Option A leans into it directly.
